一次聊天的账本闭环

1. 估算

根据输入、附件、模型、最大输出量计算费用上限。

2. 预留

数据库事务锁定可用余额；不足则不调用供应商。

3. 调用

流式返回答案，Provider Adapter 收集原始 usage。

4. 结算

输入、缓存输入、输出等分类乘调用时价格与汇率。

5. 释放

退回未使用的预留金额，写入不可变流水和调用审计。

价格版本

字段作用
provider / model供应商和精确模型标识
input / cached / output rate按供应商官方分类保存单价
billing unitToken、页、图片、请求或其他官方计费单位
currency / fx rate官方币种及折算人民币的汇率版本
source_url / effective_at官网来源和生效时间
approved_by / snapshot管理员审核人与不可变价格快照
价格更新只影响新调用。历史账单保存当时的官方单价、汇率和计算式，不因官网改价发生变化。

首版计费范围

LLM

按官方 usage 中的输入、缓存命中、输出及供应商新增分类计费。

OCR

按供应商官方页数/图片/请求单位计费，只计实际调用页面。

Embedding / Rerank

按实际 Token 或请求单位计费；重复文件命中缓存不重复收费。

平台基础设施

首版不单列存储、数据库和任务队列费用，平台自行承担。

精度与异常原则

不用浮点数

金额使用 Decimal/NUMERIC 高精度；界面显示两位，内部保留足够小数。

usage 必须可验证

无法可靠取得供应商 usage 的模型不开放生产计费，避免估算冒充实收。

失败不重复扣

幂等调用与结算；未调用成功释放预留，平台内部重试成本默认不转嫁。

人工充值可审计

记录管理员、金额、备注和时间；冲正使用新流水，不修改旧流水。
