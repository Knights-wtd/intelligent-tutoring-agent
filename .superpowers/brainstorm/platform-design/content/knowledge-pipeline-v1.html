文档导入、自生长知识库与检索流水线

OCR 只在必要页面发生；原文、页面图像、公式和版面永远保留，解析文本主要服务于搜索与引用定位。

上传到“可提问”的七阶段流水线

1. 接收与隔离

校验用户/空间权限、文件类型和大小；生成 UUID，原文件写入隔离存储。

2. 安全与去重

MIME、扩展名、ZIP 路径、压缩炸弹、恶意文件检查；SHA-256 内容去重。

3. 原生解析

PDF 文本层、DOCX 段落/图片、Markdown/Frontmatter、Obsidian 链接与附件。

4. 按页 OCR 决策

仅对无文本、乱码、低覆盖或用户强制的页面调用后台配置的 OCR API。

5. 结构与切分

章节、题号、答案、段落、页码、坐标、图片/公式锚点；保留父子层级。

6. 混合索引

Postgres 全文索引 + Embedding 向量；可选 Rerank；写入索引版本。

7. 知识自生长

后台生成概念、关系、摘要、题型和草稿笔记；按个人/班级规则发布或待审。

OCR 决策：先判断，再付费

无需 OCR 可直接提取

  • DOCX 与普通 Markdown
  • 具有有效文本层的 PDF
  • Obsidian Vault 的 Markdown 正文

图片和公式附件仍保留，并建立页面锚点。

页面级 OCR 自动触发

  • 扫描页或拍照图片
  • 提取字符数过少/乱码率高
  • 文本覆盖明显低于页面视觉区域

不是整本无条件 OCR，只计必要页。

视觉保真 最终理解

  • 公式、几何图、示意图、复杂表格
  • OCR 低置信度区域
  • 回答需要看版面关系时

检索定位后，将相关原页图像交给多模态 LLM。

识别文本不是唯一真相：回答引用同时指向原始页、文本块和页面坐标。若 OCR 与原页视觉冲突，Agent 以原页内容为准，并标记“视觉复核”。

自生长知识库的发布规则

原始证据层

课本、练习册、原始页和导入的 Obsidian 笔记；不可由 AI 覆盖。

→
AI 草稿层

章节摘要、概念卡、关系、题型、答案分析；保存 Prompt/模型/来源。

→
发布层

个人空间自动发布且可撤销；班级空间进入教师审核队列。

每个 AI 节点都保存来源、生成模型、生成时间、审核状态和版本；重新生成会创建新版本，不静默覆盖已审核内容。

零中断索引切换

Active v3 · 正在服务

继续回答用户请求；绑定旧 Embedding 签名和旧解析结果，不受后台重建影响。

Building v4 · 后台构建

管理员切换 OCR/Embedding/切分配置后建立新版本；完成数量、错误和抽样质量检查。

构建完成

原子切换 active_version_id。

→
保留旧版本

短期回滚与历史引用解析。

→
延迟清理

确认稳定后再删除旧向量。

每次提问的混合检索链

1. 问题分析

识别空间、学科、题号、引用对象和是否需要视觉。

2. 权限过滤

先限制个人/班级资源范围，再做任何搜索。

3. 双路召回

Postgres 全文/BM25 风格搜索 + pgvector 语义搜索。

4. 结构扩展

按章节、题目-答案、知识节点关系补充邻近证据。

5. 重排与视觉

可选 Rerank；必要时附相关原页截图给多模态模型。

6. 有证据回答

生成引用、页码和坐标；不足时明确区分模型补充。

成本与可靠性控制

内容哈希缓存

相同文件、相同页和相同配置不重复解析、OCR 或 Embedding。

可恢复任务

每阶段保存状态和产物；失败从断点继续，不从头重复计费。

低置信度队列

OCR/结构抽取不确定时标记复核，不把错误内容直接发布。

幂等与限流

上传和任务具有幂等键；按用户/空间限制并发、页数和预算。
