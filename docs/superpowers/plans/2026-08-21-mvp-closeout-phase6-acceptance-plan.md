# 2026-08-21 MVP 收口与 Phase 6 客户验收计划

## 决策与目标

**2026 年 8 月 21 日，项目从“完成原 Phase 5 的全部高级能力”切换为“可验收 MVP 收口”。**

交付顺序固定为：

```text
MVP 主链路收口 → 一次集中验证 → 一次 SPEC 审查 + 一次 QUALITY/SECURITY 审查
→ Phase 6 MVP 验收与客户演示 → 客户验收/下一笔资金 → 高级能力扩展
```

这不是对已完成工作的否定。现有多租户权限、知识库、题库、确定性评分、复习队列和答题历史将作为 MVP 基础；原先尚未实现的复杂 Agent 能力改为**明确延期**，不得伪称已经交付。

## MVP 交付边界

### 必须可向客户验收

1. 身份、个人/班级空间与服务端空间授权有效；跨空间资料、题目、答题历史不可读取。
2. 用户可创建知识库、上传允许的资料，并能查看处理状态。
3. 资料成功处理后，用户可检索命中内容，并打开受签名保护的来源/原页预览。
4. 用户可创建基础题目、提交答案、得到确定性评估；私有答案、rubric、提交内容及内部身份字段不在普通读取响应中泄露。
5. 用户可查看自己的复习队列和最近答题历史；后端保留按版本分页 API，完整历史分页 UI 延期到后续迭代。
6. 客户演示必须使用产品 UI 或经记录的 API 演示脚本；不允许把“仅有模型目录/哈希 embedding”描述为真实 LLM 课程辅导。
7. Phase 6 以一份最小真实端到端验收记录收口，包含一次新鲜资料的导入、处理、检索、来源打开，以及一次题目作答闭环。

### 不属于本次 MVP（延期，资金到位后扩展）

- 自生长 AI 笔记、教师审核/共享治理和知识图谱。
- L0–L3 长期记忆、多 Agent、复杂工具规划、长会话编排。
- 真实 LLM Tutor runtime、流式对话、基于 LLM 的完整解答/分步引导、真实调用计费联动。
- 高级生成式题目、教师分析/班级画像。
- 高级检索质量评估、实时 PostgreSQL 并发/性能压测、完整历史分页 UI、上传响应 DTO 收紧和非关键 coverage 追逐。

> 因此本期客户表述应为“带来源追溯的资料知识库 + 题库学习闭环 MVP”，而不是“完整 AI Tutor Agent”。后者需要可用 LLM endpoint、密钥注入、模型名、调用协议及计费验收后再进入范围。


## 独立范围审计补充（2026-08-21）

新的只读子代理审计确认：知识库已有可操作工作台页面；题库学习闭环目前仅可经 API/Swagger 演示；“AI 家教”面板是不可提交的展示壳，模型选择、余额和“回答将显示费用”的文案均未连接真实调用或结算。

因此本批 MVP 必须补齐以下**诚信与可演示性**要求：

1. 将工作台的“AI 家教”展示壳在本期改为真实、无误导的“资料检索与题库练习”界面，或隐藏其输入、模型选择和费用承诺；本期不接入真实 LLM 时，不能留下看似可用的家教对话入口。
2. 给题库 API 接入最小学习者前端流程：查看题目 → 提交作答 → 显示评估/复习时间 → 查看待复习 → 查看最近本人历史；完整历史分页 UI 不阻塞本期 MVP。题目创建可暂保留 API/教师入口。
3. 让知识库的资料处理状态可持续观察：提供受现有权限保护的刷新/查询路径，前端能明确看到“处理中 / 可搜索 / 处理失败”，而不是只停留在上传即时响应。
4. 验收材料将真实 Docker 索引失败标记为未通过证据；客户要求“上传一份新资料后立即搜索并打开来源”时，只有在新的隔离实证通过后才可给无条件 PASS。

这四项替换原批次中“实现最小 Tutor Runtime”的假设；真实 Tutor Runtime 随同真实 LLM 配置、调用计费和安全验证一并延期。
## 已知限制与诚实声明

- Task 10 在 **2026 年 8 月 19 日**的真实 Docker 纵向验收中失败：服务健康，但上传 Markdown 后索引版本为 `failed`，150 秒内搜索结果为零。不得声称真实 PostgreSQL/pgvector 导入、检索或 citation 原页链路已通过。
- Task 10 不做无依据的反复调参。为满足 MVP Gate，只允许先进行一次证据驱动的故障定位；若存在明确且小范围的根因，可作一次最小修复并与本批其余工作一起验证。若仍失败，停止修复并把“真实导入检索”作为已知交付阻塞项提交客户决定，不能伪造 PASS。
- Learning Foundation、Question Bank Task 3A、Task 3B 的冻结/stop-rule P2 记录继续保留；本计划不重新开启第三次修复。
- 用户已接受 API coverage `89.41%` 的例外。本期不会消耗时间追逐其余约 `0.59` 个百分点。

## 合并批次与审查策略

为避免逐任务重复审查，以下互相耦合的 MVP 工作视为**一个收口批次**，而非三个独立里程碑：

1. **真实资料链路 Gate：**只读定位 Task 10 失败层；如证据足够，作一次狭窄的导入/索引修复，补一条针对根因的回归测试。
2. **学习闭环可见化：**将误导性的 AI 家教展示壳降级为真实的资料检索/题库练习表述，补齐题库学习者前端入口和资料处理状态刷新；不新造真实 LLM、生成式策略或高级学习策略。
3. **MVP 演示证据：**形成可重复的最小验收脚本/清单，覆盖权限隔离、资料来源追溯与答题闭环。

批次完成后执行一次集中质量门：

- 一组只覆盖本批改动与现有关键路径的 focused tests、目标 Ruff、必要的差异/格式检查；**不运行全量测试、全量 coverage 或重复历史 Task 5 测试。**
- 一个独立 **SPEC** 审查（验收边界、权限、来源、私密字段、范围控制）。
- 一个独立 **QUALITY/SECURITY** 审查（事务/幂等、失败处理、泄密、可维护性）。
- 仅在审查发现阻断性问题时回到对应实现；不为非关键美化或指标做循环式打磨。

## Phase 6 MVP 验收门槛

- [ ] 所有 MVP 层面的服务端权限、私密字段和题目答题闭环有 focused evidence。
- [ ] 新鲜创建的隔离环境完成一次真实资料导入 → 已处理 → 检索命中 → 来源/页预览。若失败，记录为 FAIL 而非绕过。
- [ ] UI/API 演示记录覆盖知识库资料链路和题库答题/复习链路。
- [ ] 本批仅完成一次集中 SPEC 审查和一次集中 QUALITY/SECURITY 审查，结果入档。
- [ ] 客户验收包写明产品范围、已知限制、演示步骤、延期功能与后续资金对应的扩展计划。

## 执行顺序与保护规则

1. 更新根目录规划记录和本文件；保留根目录三份既有未提交记录及 feature worktree 一切既有改动。
2. 由新的独立子代理进行 MVP 范围/风险只读审计；实现仍以同一批次集中处理，不拆成重复审查。
3. 在未获得/确认 Docker 最小验收授权前，不启动 Compose、Alembic 或全量 Docker 测试；授权后只创建新的隔离项目，且不复用 2026 年 8 月 19 日的失败数据。
4. 不执行 `git add`、`git commit`、`git reset`、`git stash`、`git checkout`，不清理未提交文件。
5. Python 验证只使用 `apps/api/.venv/Scripts/python.exe`，并设置 `PYTHONDONTWRITEBYTECODE=1`；不使用系统 Anaconda Python。

## 完成定义

当且仅当 Phase 6 验收门槛有真实证据，且客户验收包已写入时，MVP 才能被称为“可验收”。如真实资料链路继续失败，MVP 可交付范围必须缩减为题库学习 API/界面和已验证的基础能力，并由用户/客户明确接受该限制。
