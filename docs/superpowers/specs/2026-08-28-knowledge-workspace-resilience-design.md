# 知识库工作区持久恢复与文件浏览器设计

日期：2026-08-28
状态：已获用户方案批准，待书面规格复核

## 1. 背景

当前知识库工作区存在四类相互关联的问题：

1. 上传、解析和知识候选生成的进度只保存在 `KnowledgePanel` 组件内存中。切换工作区标签或知识库会卸载组件，后台任务仍然执行，但前端丢失文档版本 ID、候选批次 ID 和轮询上下文，用户感知为“进程消失”。
2. 已确认的知识笔记与原始资料缺少可浏览的持久文件视图。搜索、上传、候选审核和知识正文堆叠在同一长页面中，信息层级不清晰。
3. 链路图不应持续占据知识内容页面。它需要按需打开、占据独立可视区域，并提供缩放、平移和节点导航。
4. 登录注册和 Faro 的网络连通测试不足以代表真实产品链路。必须通过浏览器会话、站内 API、知识检索和 Tutor 调用完成端到端保护。

本设计必须保留已经修复的行为：同批次重复知识标题可以确认发布；DOCX 等非分页格式不再展示虚假的“第 1 页”；Faro 中继和产品内代理配置不被绕开。

## 2. 目标

- 页面刷新、切换标签、切换知识库或重新登录后，可以从后端恢复上传文档、处理状态和最近候选批次。
- 同时以资源管理器形式展示“知识笔记”和“原始资料”。
- 点击文件后才加载并展示其内容；候选审核使用独立视图。
- 链路图默认不渲染，点击按钮后在独立全尺寸标签中打开，并支持缩放、平移、适应窗口和节点跳转。
- 为注册、登录、会话恢复、知识候选、产品内 Tutor/Faro 调用建立回归测试。

## 3. 非目标

- 本轮不实现文件重命名、拖拽移动、批量删除或自定义目录。
- 不改变知识候选生成提示词、解析算法或向量索引算法。
- 不将浏览器本地存储作为任务状态的权威来源。
- 不自动替用户确认当前 `needs_review` 批次。
- 不重构整个工作台导航或题库模块。

## 4. 方案选择

采用“后端状态恢复 + 前端资源管理器”的方案。

浏览器只保存无业务风险的展示偏好，例如目录展开状态和最近选择的文件。文档处理状态、候选批次状态和正式知识笔记全部从数据库及 API 恢复。这样不会因清理缓存、换标签或换浏览器导致业务状态丢失。

## 5. 后端设计

### 5.1 工作区快照

增加知识库工作区快照查询接口：

`GET /api/v1/knowledge-bases/{knowledge_base_id}/workspace`

返回：

- `documents`：当前知识库的原始资料，包含文档 ID、最新版本 ID、源文件名、内容类型、处理状态和时间。
- `candidate_batch`：最近一个仍需用户关注的候选批次；优先级为 `processing`、`needs_review`、`failed`，没有活动批次时可返回最近的 `confirmed` 批次或 `null`。
- `notes`：已发布的正式知识笔记摘要，包含笔记 ID、标题、层级父节点、来源文档和更新时间。

快照查询必须进行现有空间和知识库访问控制，不暴露其他租户数据。

### 5.2 正式知识笔记读取

增加：

`GET /api/v1/knowledge-bases/{knowledge_base_id}/notes/{note_id}`

返回选中笔记的标题、最新已发布 Markdown、来源标记、更新时间和父子层级信息。列表接口不返回全部正文，避免首次加载一次传输所有知识内容。

### 5.3 原始资料预览

复用现有引用预览和对象存储安全边界。工作区列表只返回元数据；用户点击原始资料后再请求预览。对于无法直接预览的格式，展示文件信息、处理状态和可搜索状态，不读取整个对象到初始页面。

### 5.4 候选批次恢复

快照接口返回活动批次的完整审核数据或足以调用现有候选批次详情接口的 ID。前端恢复后：

- `processing`：继续轮询现有候选批次详情。
- `needs_review`：恢复所有候选笔记、关系和当前审核选择。
- `failed`：显示可重试原因，但保留原始资料。
- `confirmed`：刷新正式知识笔记和链路图数据。

候选确认继续使用已有事务和重复标题限定逻辑。

## 6. 前端设计

### 6.1 页面结构

知识库页分成三层：

1. 顶部工具栏：知识库名称、任务状态、上传资料、生成候选、打开链路图。
2. 主体资源管理器：左侧文件树，右侧内容查看器。
3. 独立候选审核视图：仅在用户选择“候选审核”或活动批次需要审核时显示，不与正式笔记正文混排。

### 6.2 文件树

左侧根目录为当前知识库，固定包含：

- `知识笔记`
  - 按正式笔记层级展示。
  - 叶子项使用 `.md` 文件视觉语义。
  - 点击后请求正式笔记正文。
- `原始资料`
  - 展示 PDF、DOCX、Markdown、图片和 ZIP 等源文件。
  - 每项显示处理中、可搜索或失败状态。
  - 点击后按内容类型打开预览或文件信息。

目录默认展开。展开状态可以保存在本地，但列表内容始终由后端返回。

### 6.3 内容查看器

未选择文件时显示简洁欢迎状态和数量摘要。选择知识笔记后显示：

- 标题和层级路径。
- Markdown 正文。
- 来源资料和来源标记。
- 更新时间。

选择原始资料后显示：

- 文件名、类型和处理状态。
- 支持时显示预览。
- 不支持时显示“已完成解析并可供搜索/AI 助教使用”，避免把不能预览误判为没有读取。

### 6.4 任务状态

上传和候选生成状态不再只存在于组件本地数组。页面挂载时立即请求工作区快照，并针对活动任务继续轮询。切换工作台标签时允许终止旧组件的网络请求，但重新挂载后必须从后端恢复任务。

重复点击生成使用已有幂等键和活动批次恢复，避免创建重复任务。

## 7. 链路图设计

链路图通过顶部“打开链路图”按钮打开已有的独立工作区标签，不嵌在知识文件页面底部。

链路图标签占据主内容区域，包含：

- 缩小、放大、100%、适应窗口。
- 鼠标滚轮缩放。
- 拖动画布平移。
- 当前缩放比例。
- 点击节点打开对应知识笔记并切回知识库标签。

空图保持已有“前往候选关系审核”能力，并确保目标知识库正确。

缩放和平移仅改变客户端视图，不修改图谱数据。

## 8. 登录注册与 Faro 产品链路保护

### 8.1 身份链路

回归测试覆盖：

- 注册成功后站内会话可立即读取 `/me`。
- 登录成功后首页刷新空间列表，不停留在登录组件。
- Cookie 通过 Next.js `/api/[...path]` 代理正确转发。
- 401 会清理前端认证视图，但网络暂时失败不会伪装为“未登录”。
- 登出后会话失效，再登录可恢复工作区。

### 8.2 Faro 产品链路

验收不能只请求 Faro `/models`。必须验证：

1. 浏览器或同等真实会话登录。
2. 通过站内 Tutor API 提交问题。
3. API 使用运行时配置的 Faro 适配器和中继发起模型请求。
4. 返回非空回答。
5. 在知识库有可检索内容时返回有效引用。
6. 容器日志中没有代理、TLS 或认证错误。

测试和日志不得输出 Faro API Key。

## 9. 错误处理

- 工作区快照失败：保留页面框架并提供“重新加载”，不清空已知 UI 状态。
- 单个文件正文失败：只在查看器显示错误，不使整个知识库不可用。
- 候选轮询失败：显示“任务仍在后台执行，可重新连接”，下次加载继续恢复。
- Tutor/Faro 失败：区分未登录、模型服务暂不可用和知识检索无结果，不将所有错误归为网络问题。

## 10. 测试策略

遵循失败测试先行：

- API：工作区快照访问控制、状态优先级、文档列表、正式笔记详情、重复标题发布保护。
- Web：组件卸载后重新挂载可以恢复 processing/needs_review 批次；文件树双目录；点击后懒加载正文；链路图按需打开与缩放控制；登录注册代理行为。
- Tutor：通过产品 API 的真实适配器边界测试，另做运行容器中的真实 Faro 冒烟测试。
- 全量：API、Web、Ruff、TypeScript/Next build、`git diff --check`。
- 部署：重建 API、Worker、Web，检查健康端点和产品内端到端路径。

## 11. 迁移和兼容性

优先通过现有数据表查询构建快照。如果正式笔记当前无法表达父级，则从已发布的结构链接计算父子关系，避免为本轮 UI 引入高风险数据库迁移。

新增 API 为向后兼容扩展；现有上传、搜索、候选和图谱接口保持不变。

## 12. 验收标准

- 上传或生成候选时切到其他标签，再返回后仍显示真实进度。
- 刷新网页后仍能看到活动批次；完成后可直接审核。
- 文件树同时显示知识笔记和原始资料。
- 点击文件才加载正文或预览。
- 知识正文与链路图不在同一个滚动区块中。
- 链路图通过按钮打开后立即位于主视区，并支持缩放和平移。
- 登录、注册、刷新会话和空间加载均通过。
- 产品内 Tutor 调用真实 Faro 成功，而不仅是网络连通测试成功。
- 既有重复标题确认和 DOCX 非分页引用测试继续通过。
