# 前端未显示排查指南

> 适用于：项目启动后浏览器里只有几行 JSON、API 文档或错误文本，看不到完整的学习工作区前端。
>
> 使用方法：把下面“可直接复制给 AI 的提示词”完整复制给你的 AI 编程助手，并把它放在项目仓库根目录执行。不要先让 AI 猜测，要求它先检查实际文件、端口和容器状态。

## 可直接复制给 AI 的提示词

```text
你现在要帮我排查这个项目“启动后没有前端、浏览器只显示几行字”的问题。

请先确认当前工作目录是项目仓库根目录，不要凭经验猜路径。这个项目的前端位于 apps/web，前端是 Next.js；后端 API 默认在 8000 端口，Web 前端默认在 3000 端口。打开 http://localhost:8000 看到 JSON、健康检查或 API 文档，不代表前端启动成功；正常页面应打开 http://localhost:3000。

请按以下顺序执行检查，并把每一步的实际输出和结论告诉我：

1. 确认目录和前端文件：
   - PowerShell: Get-Location
   - PowerShell: Test-Path .\apps\web\package.json
   - PowerShell: Get-Content .\apps\web\package.json
   - PowerShell: Get-Content .\package.json

2. 如果使用 Docker：
   - 执行 docker compose config --services
   - 执行 docker compose ps
   - 检查 web、api、postgres、redis、minio、worker 是否存在，以及 web 是否为 Up/healthy
   - 执行 docker compose logs --tail=200 web
   - 如果 web 没有运行，执行 docker compose up -d --build web
   - 如果 web 构建失败，不要只说“前端没了”，要指出第一个真实错误行和对应文件

3. 如果使用本地开发模式：
   - 确认已经在仓库根目录执行 corepack enable
   - 确认已经执行 pnpm install --frozen-lockfile
   - 确认前端启动命令是 pnpm dev:web，而不是只启动 uvicorn
   - 执行 pnpm dev:web，并检查终端是否显示 Local: http://localhost:3000
   - API 需要另一个终端启动，但只启动 API 不会自动启动前端

4. 检查端口：
   - PowerShell: Test-NetConnection localhost -Port 3000
   - PowerShell: Test-NetConnection localhost -Port 8000
   - PowerShell: Invoke-WebRequest http://localhost:3000 -UseBasicParsing
   - 如果 3000 不通而 8000 能通，结论应是 Web 服务没有启动、启动失败或访问了错误端口

5. 检查浏览器访问地址：
   - 正常前端地址：http://localhost:3000
   - API 地址：http://localhost:8000
   - 不要把 API 的 8000 端口误当成前端地址
   - 如果使用了自定义 WEB_PORT/API_PORT，请从 .env、compose.yaml 和 docker compose ps 中确认真实映射

6. 检查 API 地址配置：
   - 查看 .env 中 NEXT_PUBLIC_API_BASE_URL
   - 本项目默认让浏览器使用同源的 `/api/*` 路径；本地开发和 Docker 部署通常都可以把 NEXT_PUBLIC_API_BASE_URL 留空
   - Docker 部署时，Web 服务通过 `API_INTERNAL_URL=http://api:8000` 在服务器端访问 API；不要把 `http://api:8000` 直接填给浏览器，因为 `api` 只是 Docker 内部服务名
   - 只有确实要让浏览器直接访问 API 时，才设置 NEXT_PUBLIC_API_BASE_URL=http://localhost:8000；这时要确保 API 端口已对宿主机开放
   - NEXT_PUBLIC_API_BASE_URL 是 Next.js 构建时变量，修改后必须重新启动开发服务器或重新构建 web 镜像
7. 最后给出明确分类：
   A. 访问错端口；
   B. 只启动了 API，没有启动 Web；
   C. web 容器没有创建或已退出；
   D. 前端依赖未安装/Node/pnpm 版本不匹配；
   E. 前端构建失败；
   F. 前端已启动，但 API 地址或跨域配置错误。

请不要修改代码来掩盖问题。只有在找到真实原因后，才给出最小修复命令；如果需要修改文件，请先说明文件的绝对路径、修改原因和修改后的验证命令。
```

## 正确启动方式

### Docker 方式

在仓库根目录执行：

```powershell
Copy-Item .env.example .env
# 编辑 .env，填入必要配置

docker compose up -d --build
docker compose ps
```

前端地址：

```text
http://localhost:3000
```

API 地址：

```text
http://localhost:8000
```

查看前端日志：

```powershell
docker compose logs -f web
```

如果只执行了下面的命令：

```powershell
docker compose up -d api
```

那么只能启动 API，不会有前端页面。

### 本地开发方式

需要两个终端。

终端一：启动 API。

```powershell
Set-Location apps/api
& .\.venv\Scripts\python.exe -m uvicorn tutor_api.main:app --reload
```

终端二：从仓库根目录启动 Web。

```powershell
corepack enable
corepack prepare pnpm@11.19.0 --activate
pnpm install --frozen-lockfile
pnpm dev:web
```

然后访问：

```text
http://localhost:3000
```

## 最常见的误区

### 误区 1：打开了 8000 端口

看到几行 JSON、`健康检查`、Swagger 或 API 错误，通常说明打开的是 API：

```text
http://localhost:8000
```

前端应该打开：

```text
http://localhost:3000
```

### 误区 2：只启动了后端

`uvicorn tutor_api.main:app --reload` 只启动 FastAPI，不会启动 Next.js。必须另开终端执行：

```powershell
pnpm dev:web
```

### 误区 3：Web 容器启动失败但没有看日志

先执行：

```powershell
docker compose ps -a
docker compose logs --tail=200 web
```

重点看第一个 `Error`、`failed`、`Cannot find module`、`ELIFECYCLE` 或端口占用错误，不要只看最后一行“退出”。

### 误区 4：把 Docker 内部 API 地址给浏览器使用

浏览器不能解析 Docker Compose 的服务名 `api`。下面这种配置对浏览器通常是错的：

```env
NEXT_PUBLIC_API_BASE_URL=http://api:8000
```

浏览器应使用宿主机地址，例如：

```env
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

修改后要重新构建 Web：

```powershell
docker compose up -d --build web
```

### 误区 5：在错误目录执行命令

必须能看到这些文件/目录：

```text
apps/web/package.json
apps/api/
compose.yaml
.env.example
package.json
```

如果看不到，先切换到真正的仓库根目录，再执行启动命令。

## 给项目作者的快速判断

```powershell
# 当前目录是否为仓库根目录
Get-Location
Test-Path .\compose.yaml
Test-Path .\apps\web\package.json

# Docker 前端状态
docker compose ps -a web

# Web 是否真的监听 3000
Test-NetConnection localhost -Port 3000

# API 是否监听 8000
Test-NetConnection localhost -Port 8000
```

判断规则：

- `3000=失败，8000=成功`：前端没启动或访问错端口。
- `3000=成功，页面是错误信息`：检查 `docker compose logs web` 和 API 地址配置。
- `3000=成功，8000=失败`：前端已启动，但后端未启动，登录/数据请求会失败。
- `web=Exited`：先看 Web 容器日志，不要先改业务代码。
- `web=Up` 且 3000 可访问：前端服务已经存在，问题通常在浏览器地址、API 地址或登录状态。
